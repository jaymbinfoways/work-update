Daily Work & Attendance Tracker
Technical Specification & Development Brief
1. Project Overview
Build a personal Daily Work Update & Attendance Management System. The application allows the user to enter daily work updates in natural language, automatically clean and correct the text using OpenAI, extract structured information, and store it in a database.
The application must provide:
Daily work update management.
Attendance tracking: Present, WFH, Leave, Holiday, Half Day.
Module/project-wise work history.
Deployment status tracking: Dev, UAT, Production, Pending.
Search and filters.
Monthly attendance statistics.
Module-wise statistics and history.
Deployment history.
Monthly summaries and exports.
2. Recommended Architecture
User  ↓Frontend / API  ↓AI Service (OpenAI)  ↓Structured JSON  ↓Backend validation + business logic  ↓PostgreSQL database  ↓Dashboard / Reports / SearchOptional:Database → Google Sheets sync/exportExternal client / ChatGPT integration → Your API

4. Core Design Principle
Do not store only the final formatted paragraph. Always store both the original raw input and the structured/processed information. This allows future searching, auditing, reporting, and re-processing.
{  "raw_input": "helpdesk added dynamic theme config and fixed code",  "processed": {    "module": "Helpdesk",    "status": "DEV",    "tasks": [      {        "description": "Implemented dynamic theme configuration and updated the code accordingly."      }    ]  }}

6. AI Processing
The AI must:
Correct grammar and spelling.
Standardize module names when possible.
Standardize deployment statuses.
Extract individual tasks.
Preserve the user's original meaning.
Never invent work.
Return structured JSON matching the strict schema.
Generate a clean formatted version for display.
7. AI Output Schema
{  "date": "2026-08-07",  "attendance": "UNMARKED",  "formatted_output": "07-08-26\n\nHelpdesk (Deployed on Dev)\n...",  "work_items": [    {      "module": "Helpdesk",      "deployment_status": "DEV",      "tasks": [        {          "description": "Implemented dynamic theme configuration and updated the code accordingly."        }      ]    }  ]}
8. AI System Rules
You are a professional work-update formatter.Rules:1. Never invent a task.2. Never remove a meaningful task.3. Preserve the user's original meaning.4. Correct grammar and spelling.5. Use professional technical language.6. Standardize module names when possible.7. Standardize deployment statuses.8. Extract every task separately.9. If deployment status is not provided, use NOT_APPLICABLE.10. Do not assume attendance unless explicitly provided.11. Normalize provided dates to YYYY-MM-DD.12. Return data according to the provided strict JSON schema.13. Generate a clean formatted_output.14. Keep descriptions concise.15. Do not add explanations outside the requested structured output.

16. Attendance Logic
Do not automatically assume that an update exists means the user was Present.
Explicit Present → PRESENT.
Explicit WFH → WFH.
Explicit Leave → LEAVE.
Explicit Holiday → HOLIDAY.
No attendance information → UNMARKED.
Provide a convenient 'Mark today as Present' option when saving an update.
17. Attendance Calendar
Provide a monthly calendar. Clicking a date should show its attendance and daily work update. Dates should be markable as Present, WFH, Leave, Holiday, Half Day, or Unmarked.

28. Recommended Final User Experience
Every day:User opens dashboard      ↓Clicks "+ Add Today's Update"      ↓Pastes whatever they wrote      ↓Clicks "Process with AI"      ↓AI fixes grammar + extracts structure      ↓User reviews      ↓Clicks "Save Update"      ↓Attendance/work history/dashboard automatically updateTarget: normal daily update should take less than 30 seconds.
29. Key Product Decision
PostgreSQL should be the source of truth. Google Sheets should be an optional export/synchronization layer. This provides reliable search, relationships, statistics, reporting, and future integrations while still allowing the user to access the information in a spreadsheet.
